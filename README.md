This container setup uses pihole and dnscrypt-proxy in conjunction.

Default config routes 8100 to 80 for pihole http and 4433 to 433 for 
pihole https to avoid conflict with any existing web containers.

Remove .example from both the pihole.toml and dnscrypt-proxy configs
before running.

Docker container configured to use external network sozuholenet.
Create first with:
> docker network create -d bridge sozuholenet


DNSCrypt-Proxy uses a bind mount to store its configuration here:
```
└── dnsproxyconfig
    └── dnscrypt-proxy.toml
```
./dnsproxyconfig needs to be chown nobody:nogroup dnscrypt-proxy to write files.

In this supplied config file, a few UK/EU resolves are defined at the top. 
Look for the list and choose your own.

* Logging is disabled by defining the logfile paths as ''
* Application loglevel is set to 6 (Fatal only), change if you need to debug.


PiHole uses a bind mount to store its configuration and logfiles:
```
├── etc-pihole
│   └── pihole.toml
└── logs
    ├── FTL.log
    ├── pihole.log
    └── webserver.log
```
All other files will be autogenerated, only these two paths and files need exist 
before docker compose up -d


Inside pihole, the upstream DNS needs to be configured to dnscrypt-proxy#5053 which should
be the value in the example config.
