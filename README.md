This container setup uses pihole and dnscrypt-proxy in conjunction.

Default config routes 8100 to 80 for pihole http and 4433 to 433 for 
pihole https to avoid conflict with any existing web containers.

## Before docker compose up -d
Remove .example from both the pihole.toml and dnscrypt-proxy configs.

Edit .env file and add IP of your host adapter. This
is because port 53 gets mapped directly to host to avoid recursive
DNS lookups inside the container due to Docker's internal networking.

Alternative is to use network_mode:host, not bridge, but this might
conflict if you have other services running on the same host.

## Mounts
DNSCrypt-Proxy uses a bind mount to store its configuration here:
```
└── dnsproxyconfig
    └── dnscrypt-proxy.toml
```
./dnsproxyconfig needs to be chown nobody:nogroup dnscrypt-proxy to write files.

In this supplied config file, a few UK/EU resolvers are defined at the top. 
Look for the list and choose your own.

* Logging is disabled by defining the logfile paths as ''
* Application loglevel is set to 6 (Fatal only), change if you need to debug.


PiHole uses a bind mount to store its configuration and logfiles:
```
├── etc-pihole
│   └── pihole.toml
└── logs
    ├── FTL.log
    ├── pihole.log
    └── webserver.log
```
All other files will be autogenerated, only these two paths and files need 
exist before docker compose up -d

## PiHole Setup
Inside pihole, the upstream DNS needs to be configured to dnscrypt-proxy#5053 
which should be the value in the example config.

Changes to your pihole config should persist to /etc-pihole/pihole.toml

## Updates
If you see an update notification at the bottom of the pihole UI, head to the 
terminal and > docker compose pull  to bring the latest pihole container down.
